# roadmap

the current work is about making a local writing gate easier to trust and adopt: a deterministic public fixture scorecard, PR content summaries, normalized block/review/signal output, profile readiness, consent-bound team bundles, a compact MCP core, opt-in delivery checks, and a rule contribution contract.

HYV is not an authorship detector, an AI detector, or a service that proves facts. Its local checks create inspectable editorial and source-consistency evidence. Publishing remains a human decision.

good first contributions: add a documented counterexample to an existing rule, improve a local host recipe, or tighten one docs-contract test without changing public CLI behavior.

| question | HYV answer |
| --- | --- |
| did AI write this? | HYV does not determine authorship. |
| is this fact true? | HYV checks only against local evidence you supply. |
| does this preserve the writer? | VoiceDNA reports observable drift against local samples. |
| can a team share a profile safely? | A consent-bound bundle carries fingerprints and expiry metadata, never samples. |
